Fondamentaux · C.00

Pourquoi le C# d'abord

Sage 100 Objets Métiers est une bibliothèque ActiveX (COM) : Objets100c.dll. Elle n'impose aucun langage — la documentation officielle alterne VB.NET et C# — mais dans un projet moderne .NET, le C# est devenu le choix par défaut pour trois raisons concrètes.

1. Le typage fort évite des erreurs coûteuses. Les objets métiers Sage exposent des dizaines de propriétés typées (eTiersType, eDocumentType…) : le compilateur C# refuse un mauvais type à la compilation, là où un langage plus permissif ne le détecterait qu'à l'exécution, en pleine transaction comptable.

2. L'interop COM est native. C# dialogue avec une DLL ActiveX via de simples références — using Objets100cLib; — sans couche de traduction.

3. L'écosystème. ASP.NET Core, Entity Framework, les API REST : tout l'outillage autour de Sage (portails clients, synchronisations, connecteurs) s'écrit aujourd'hui en C#.

⚠️ Attention

La documentation Sage montre souvent du VB.NET historique (Dim, ByVal, End Sub). Ce cours traduit systématiquement ces exemples en C# idiomatique — la logique métier reste identique, seule la syntaxe change.

📌 À retenir

Sage 100 Objets Métiers ne « préfère » aucun langage : c'est votre projet qui doit choisir un langage cohérent avec le reste de votre stack. Ici : C#.

Fondamentaux · C.01

Premier programme & environnement

Un programme C# minimal, une fois le SDK .NET installé, tient en quelques lignes :

C#
1using System;
2
3namespace PremierProgramme
4{
5    class Program
6    {
7        static void Main(string[] args)
8        {
9            Console.WriteLine("Bonjour, Sage 100c !");
10        }
11    }
12}

Trois éléments à repérer : le namespace (espace de nom, évite les collisions de noms entre bibliothèques — utile puisque Sage expose son propre espace Objets100cLib), la classe qui contient le code, et la méthode Main, point d'entrée exécuté au lancement.

Pour un projet interagissant avec Sage 100c, l'environnement recommandé est Visual Studio avec un projet Console App (.NET Framework) ou WinForms — la documentation Sage précise que l'environnement minimal est Microsoft Windows 7 SP1, et que la référence COM Objets100c.dll doit être ajoutée via « Ajouter une référence → COM ».

🔧 Sage

Le kit de développement Sage installe, entre autres, un projet d'exemple ExempleWindows.sln en VB.NET : un bon complément pour comparer la syntaxe aux exemples C# de ce cours.

Fondamentaux · C.02

Variables, types & opérateurs

C# distingue les types valeur (stockés directement : int, double, bool, DateTime) des types référence (une variable pointe vers un objet : string, les classes, les interfaces Sage comme IBOTiers3).

C#
1string numeroTiers = "CARAT";
2double solde = 0d;
3bool estMouvemente = false;
4DateTime dateInventaire = new DateTime(2026, 12, 31);
5decimal montantHT = 1250.75m;   // decimal : précis pour les montants

Cette rigueur compte particulièrement avec Sage : les montants (D_Cours, EA_Montant…) doivent être manipulés en double ou decimal selon l'interface — jamais en float, dont l'imprécision est incompatible avec des écritures comptables.

Les opérateurs classiques (+ - * / %, comparaison == != < >, logiques && ||) s'appliquent normalement. Un piège fréquent : la division entière — 7 / 2 vaut 3 si les deux opérandes sont des int, alors que Sage attend souvent un résultat décimal (7.0 / 2).

💡 Astuce

Utilisez var quand le type est évident (var client = base100c.FactoryClient.ReadNumero("CARAT");) : le code reste typé fort, seule l'écriture est allégée.

✅ Quiz de validation

Fondamentaux · C.03

Structures de contrôle

Les structures conditionnelles et boucles pilotent la logique métier. Exemple : parcourir une collection Sage et appliquer une règle selon le type de tiers.

C#
1foreach (IBOTiers3 tiers in factoryTiers.QueryActifOrderNumero())
2{
3    if (tiers.CT_Type == TiersType.TiersTypeClient)
4    {
5        Console.WriteLine($"Client : {tiers.CT_Intitule}");
6    }
7    else if (tiers.CT_Type == TiersType.TiersTypeFournisseur)
8    {
9        Console.WriteLine($"Fournisseur : {tiers.CT_Intitule}");
10    }
11    else
12    {
13        Console.WriteLine("Autre tiers");
14    }
15}

foreach est la boucle de prédilection avec les collections Sage (IBICollection implémente l'énumération COM standard). for et while restent utiles pour un parcours indexé ou une condition de sortie explicite. Le switch expression (C# moderne) est élégant pour aiguiller sur un énumérateur :

C#
1string Libelle(TiersType t) => t switch
2{
3    TiersType.TiersTypeClient      => "Client",
4    TiersType.TiersTypeFournisseur => "Fournisseur",
5    TiersType.TiersTypeAutre       => "Autre tiers",
6    _                               => "Inconnu"
7};

⚠️ Attention

Ne modifiez jamais une collection Sage pendant un foreach qui la parcourt (ajout/suppression) : préférez copier les références dans une List<T> avant modification.

Fondamentaux · C.04

Méthodes (paramètres, out, valeurs par défaut)

Les méthodes C# structurent le code. Trois mécanismes reviennent souvent dans les exemples Sage traduits depuis VB.NET (ByVal/ByRef) :

C#
1// Paramètre par défaut (équivalent Optional ByVal ... = valeur)
2bool OuvreBaseCpta(BSCPTAApplication100c baseCpta, string nomBase,
3                    string utilisateur = "", string motDePasse = "")
4{
5    try
6    {
7        baseCpta.Name = nomBase;
8        baseCpta.Loggable.UserName = utilisateur;
9        baseCpta.Loggable.UserPwd  = motDePasse;
10        baseCpta.Open();
11        return true;
12    }
13    catch (Exception ex)
14    {
15        Console.WriteLine("Erreur en ouverture de base comptable : {0}", ex.Message);
16        return false;
17    }
18}
19
20// Paramètre out (équivalent ByRef en sortie)
21bool TryLireTiers(IBOTiersFactory3 factory, string numero, out IBOTiers3 tiers)
22{
23    tiers = factory.ExistNumero(numero) ? factory.ReadNumero(numero) : null;
24    return tiers != null;
25}

ref transmet une variable par référence dans les deux sens (lecture et écriture) — c'est l'équivalent direct du ByRef massivement utilisé dans les exemples officiels Sage (Sub OuvreBaseCpta(ByRef BaseCpta As BSCPTAApplication100c, ...)). out impose que le paramètre soit assigné avant le retour de la méthode : idéal pour un pattern « essayer de lire, indiquer le succès ».

📌 À retenir

ByVal (VB.NET) → paramètre normal en C#. ByRef (VB.NET) → ref ou out en C#, selon que la valeur d'entrée compte ou non.

Fondamentaux · C.05

Exceptions (try/catch/finally)

Sage 100 Objets Métiers signale ses erreurs (violation de contrôle de cohérence, échec de connexion, verrou…) par des exceptions .NET standard. La documentation officielle recommande systématiquement d'encadrer les appels sensibles :

C#
1try
2{
3    baseCial.CompanyServer       = server;
4    baseCial.CompanyDatabaseName = database;
5    baseCial.Loggable.UserName   = user;
6    baseCial.Loggable.UserPwd    = pwd;
7    baseCial.Open();
8}
9catch (Exception ex)
10{
11    Console.WriteLine("Erreur en ouverture de base commerciale : {0}", ex.Message);
12}
13finally
14{
15    // Exécuté systématiquement, succès ou échec : libération de ressources
16    Console.WriteLine("Tentative de connexion terminée.");
17}

Pour les processus métiers (IPMSortirLots, IPMInventaire, IPMTransformation…), Sage utilise un pattern légèrement différent : CanProcess() vérifie la cohérence sans lever d'exception, et les erreurs détaillées se récupèrent dans une collection IFailInfoCol :

C#
1if (processConversion.CanProcess())
2{
3    processConversion.Process();
4}
5else
6{
7    for (int i = 1; i <= processConversion.Errors.Count; i++)
8    {
9        IFailInfo failInfo = processConversion.Errors[i];
10        Console.WriteLine(failInfo.Text);
11    }
12}

⚠️ Attention

Ne jamais catch (Exception) silencieusement autour d'une écriture (Write()) : vous perdriez la cause exacte d'un rejet de contrôle de cohérence, essentielle pour diagnostiquer un problème de saisie.

Fondamentaux · C.06

POO : classes, objets, interfaces, héritage

La documentation Sage définit ces notions presque mot pour mot comme le fait C# : « Une classe peut être comparée à un moule destiné à fabriquer des objets » ; « une interface peut être considérée comme un schéma à partir duquel de nouveaux objets peuvent être créés ». C'est exactement le vocabulaire orienté-objet de C#.

C#
1public interface IPersonne
2{
3    string Nom { get; set; }
4    string Presenter();
5}
6
7public class Employe : IPersonne
8{
9    public string Nom { get; set; }
10    public string Service { get; set; }
11
12    public string Presenter() => $"{Nom} — service {Service}";
13}

Dans Sage 100 Objets Métiers, l'héritage d'interface est omniprésent : IBOTiers3 hérite de IBIPersistObject (méthodes Read(), Write(), Remove() communes à tous les objets persistants), tandis que IBOClient3 ajoute des propriétés spécifiques au-dessus de IBOTiersPart3. Comprendre l'arbre d'héritage d'une interface Sage, c'est savoir où chercher une propriété : dans l'interface elle-même, ou dans une interface héritée documentée juste au-dessus dans le manuel.

📌 À retenir

Objet = instance d'une classe. Classe = « moule ». Interface = contrat de méthodes/propriétés que la classe s'engage à fournir. Encapsulation = l'implémentation interne (le code) reste invisible ; seule l'interface est exposée à l'utilisateur de l'objet — exactement le modèle publié par Objets100c.dll.

✅ Quiz de validation

Fondamentaux · C.07

Collections & généricité

C# propose des collections génériques fortement typées (List<T>, Dictionary<TKey,TValue>) qui complètent — sans jamais remplacer — les collections COM exposées par Sage (IBICollection, IBICollectionPredicate).

C#
1// Copier une collection Sage dans une liste générique .NET
2List clientsActifs = new List();
3foreach (IBOTiers3 t in factoryTiers.QueryActifOrderNumero())
4{
5    if (t.CT_Type == TiersType.TiersTypeClient)
6        clientsActifs.Add(t);
7}
8
9// Puis manipuler avec LINQ, sans jamais modifier la collection Sage en cours de lecture
10var soldeTotal = clientsActifs.Sum(c => c.Solde());
11var top10 = clientsActifs.OrderByDescending(c => c.Solde()).Take(10);
12

Cette étape — copier vers une liste .NET puis traiter — est une pratique recommandée dans les intégrations Sage : elle isole votre logique métier du cache applicatif COM, évite les effets de bord si un autre objet modifie la même collection, et vous ouvre tout l'outillage LINQ (tri, filtre, agrégation) que Sage 100 Objets Métiers ne propose pas nativement.

🔧 Sage

IBICollectionPredicate (utilisée avec les prédicats) fonctionne comme IBICollection : Count, Item, AddNew(), Remove(), RemoveAll() — le même vocabulaire de collection COM, mais orientée « pointeurs » pour l'optimisation.

Sage 100 Objets Métiers · S.00

Présentation (ActiveX COM, Objets100c.dll)

Sage 100 Objets Métiers se présente sous la forme d'une bibliothèque logicielle ActiveX destinée à simplifier le développement d'applications accédant aux bases de données Sage 100c (SQL Server et SQL Server Express). Cet ActiveX — le fichier Objets100c.dll — met à disposition des développeurs des classes, interfaces, méthodes et propriétés permettant l'accès en lecture et en écriture à ces bases.

Deux garanties structurantes accompagnent chaque écriture :

  • Contrôles de cohérence automatiques lors de l'ajout ou la modification de données.
  • Automatismes : initialisation de champs avec des valeurs par défaut ou héritées lors de la création d'un enregistrement (article, tiers, document…).

Le kit de développement installe trois éléments : Objets100c.dll (l'ActiveX lui-même), un classeur CA Articles.xls d'exemple, et un répertoire Annuaire contenant un projet Visual Basic .NET complet. L'installation ne nécessite aucune clé de licence — en revanche, la distribution d'une application cliente exige d'installer l'ActiveX via le Runtime utilisateur, jamais via le kit de développement.

🔧 Sage

Certains types de documents restent hors de portée de Sage 100 Objets Métiers, en création comme en lecture : Facture Comptabilisée, Archive, Dépréciation de stock et Tickets.

Terminologie · S.01

Concepts fondamentaux

Le manuel officiel pose neuf notions, qui recoupent presque terme à terme le vocabulaire orienté-objet vu en Partie I :

Exemple emblématique de la chaîne complète : BSCPTAApplication100c (classe Application) → IBOTiersFactory3 (interface Factory) → IBOTiers3 (interface objet métier).

Mise en œuvre · S.02

Installation & référencement

Deux publics, deux installations distinctes :

  • Le poste développeur installe le Kit de développement (kitobjets100c_100.exe), qui pose Objets100c.dll, le classeur d'exemple et le projet Annuaire. Aucune clé de licence n'est requise à ce stade.
  • Le poste client (déploiement de l'application finie) reçoit uniquement l'ActiveX via le Runtime utilisateur — jamais le kit de développement complet.

Dans Visual Studio, le référencement s'effectue par « Ajouter une référence → Onglet COM → Objets100c ». Le projet importe ensuite l'espace de noms :

C#
1using Objets100cLib;

Sage évoque un mécanisme Side by Side avec manifeste applicatif : plusieurs versions de l'ActiveX peuvent cohabiter sur un même poste, chaque application référençant, via son manifeste, la version qu'elle attend — évitant qu'une mise à jour Sage 100c ne casse une intégration existante développée pour une version antérieure.

⚠️ Attention

N'installez jamais le kit de développement sur les postes clients en production : seul le Runtime, plus léger et sans outillage de développement, doit y être déployé.

Cpta & Cial · S.03

Connexion aux bases

Deux classes Application, deux méthodes de connexion analogues :

1private static bool OuvreBaseCpta(ref BSCPTAApplication100c baseCpta, string nomBase,
2                                   string utilisateur = "", string motDePasse = "")
3{
4    try
5    {
6        baseCpta.Name = nomBase;
7        baseCpta.Loggable.UserName = utilisateur;
8        baseCpta.Loggable.UserPwd  = motDePasse;
9        baseCpta.Open();
10        return true;
11    }
12    catch (Exception ex)
13    {
14        Console.WriteLine("Erreur en ouverture de base comptable : {0}", ex.Message);
15        return false;
16    }
17}
18

21{

Factory, Create, Read, Write · S.04

Cycle de vie d'un objet

Chaque enregistrement d'une base Sage 100c est vu comme un objet issu de l'interface IBIPersistObject. Pour créer ou lire cet objet, on passe systématiquement par une propriété Factory, elle-même issue de l'interface IBITypeObjectFactory.

C#
1// Création d'un nouvel objet Tiers
2IBOTiersFactory3 factoryTiers = baseCpta.FactoryTiers;
3IBOTiers3 nouveauTiers = factoryTiers.Create();
4nouveauTiers.CT_Num     = "NOUVCLI";
5nouveauTiers.CT_Intitule = "Nouveau client";
6nouveauTiers.CT_Type    = TiersType.TiersTypeClient;
7nouveauTiers.Write();          // persistance immédiate en base
8// ou WriteDefault() : valide d'abord les valeurs par défaut manquantes, puis écrit
9
10// Lecture d'un objet existant
11IBOTiers3 carat = factoryTiers.ReadNumero("CARAT");

Le cache applicatif joue un rôle central : la première lecture d'un enregistrement le charge en mémoire ; toute lecture ultérieure du même enregistrement (même via un autre objet) réutilise ce cache — accélération des accès, et cohérence garantie entre plusieurs références au même enregistrement. La méthode Read() force une relecture depuis la base ; Refresh() ne relit que si les données en base diffèrent réellement du cache, limitant les allers-retours réseau.

⚠️ Attention

En accès multi-utilisateurs, un enregistrement modifié par une autre application ne se reflète pas automatiquement dans votre cache local : appelez Read() ou Refresh() avant toute décision critique basée sur des données potentiellement obsolètes.

✅ Quiz de validation

Lecture d'ensembles · S.05

Collections & cache applicatif

Lire plusieurs enregistrements passe par les méthodes Queryxxx() exposées sur chaque Factory, qui retournent un objet IBICollection :

C#
1IBICollection clientsActifs = baseCpta.FactoryTiers.QueryActifOrderNumero();
2
3foreach (IBOTiers3 tiers in clientsActifs)
4{
5    Console.WriteLine($"{tiers.CT_Num} — {tiers.CT_Intitule} — solde {tiers.Solde():C}");
6}
7
8Console.WriteLine($"Nombre de tiers actifs : {clientsActifs.Count}");

Chaque interface Factory publie ses propres méthodes de requête pré-définies (QueryActifOrderNumero(), QueryTypeNumeroOrderNumero(), QueryReplicate()…). C'est une différence fondamentale avec les prédicats (voir S.09) : les critères d'une méthode Query sont fixés par Sage, tandis qu'un prédicat autorise des critères entièrement paramétrables au moment de l'appel.

Le cache applicatif s'applique également aux collections : parcourir deux fois la même collection ne recharge pas systématiquement chaque objet depuis la base si celui-ci est déjà en mémoire. Ce comportement accélère les traitements de masse, mais impose la discipline vue en S.04 (Read()/Refresh()) dès qu'une donnée doit être garantie fraîche.

💡 Astuce

La propriété ListForward, apparue avec les prédicats, remplace avantageusement List : elle bénéficie des mêmes optimisations « pointeurs » que les prédicats, sans nécessiter d'en écrire un.

Maître / sous-objet · S.06

Liens entre objets

De nombreux objets métiers Sage s'organisent en relation maître / sous-objet : un document de vente (objet maître, IBODocumentVente3) possède une collection de lignes (sous-objets, IBODocumentVenteLigne3), chaque ligne référençant à son tour un article.

C#
1IBODocumentVente3 doc = baseCial.FactoryDocumentVente.CreateType(DocumentType.DocumentTypeVenteLivraison);
2doc.SetDefaultClient(baseCial.CptaApplication.FactoryClient.ReadNumero("CARAT"));
3doc.WriteDefault();                       // l'entête devient persistante
4
5IBODocumentVenteLigne3 ligne = doc.FactoryDocumentLigne.Create();
6ligne.SetDefaultArticle(baseCial.FactoryArticle.ReadReference("ARTICLE_LOT"), 30);
7ligne.Write();

Cette structuration se retrouve aussi côté comptable : une écriture (IBOEcriture3) possède ses sections analytiques via FactoryEcritureA.List ; un compte général peut fabriquer un tiers rattaché via IBOCompteGTiersFactory3. Le principe général : l'objet maître expose une propriété Factory de sous-objet (souvent nommée Factory<NomDuSousObjet>), qui crée ou liste les sous-objets rattachés à cette instance précise.

📌 À retenir

SetDefaultXxx() est un pattern récurrent : il initialise un sous-objet ou une propriété avec les valeurs par défaut héritées de l'objet passé en paramètre (client, article…), en respectant les règles métier Sage (tarification, TVA, etc.).

IStream · S.07

Identifiants & sérialisation

Chaque enregistrement Sage 100c dispose d'un identifiant unique, sérialisable via l'interface IBIPersistStream (implémentée notamment par les classes Application elles-mêmes, qui gèrent la « base » comme un flux). Cette sérialisation permet de conserver la référence exacte d'un enregistrement — indépendamment de son numéro métier, qui pourrait théoriquement changer — pour la retrouver plus tard sans repasser par une recherche complète.

Concrètement, un identifiant Sage (IBIObjectID) accompagne les méthodes bas niveau comme Read(IBIObjectID pOID, ...) exposées par IBITypeObjectFactory — une alternative aux méthodes ReadNumero()/ReadReference() plus lisibles au quotidien, mais utile pour des mécanismes internes (réplication, synchronisation d'identifiants entre applications).

🔧 Sage

Le manuel officiel classe la « Gestion des identifiants » aux côtés du Processus de conversion d'un prospect en client : un identifiant stable est ce qui permet à Sage de faire évoluer un enregistrement (prospect → client) sans en perdre la traçabilité.

📌 À retenir

Deux interfaces à distinguer : IBIPersistObject (le contrat « objet métier persistant » avec Read/Write/Remove) et IBIPersistStream (le contrat « flux/base » sérialisable, implémenté par les classes Application).

IPredicate, IPredicateBuilder, QueryPredicate · S.09

Prédicats

Publiés à partir de la version 10.05, les prédicats retournent une collection (IBICollection) triée et filtrée sur des critères entièrement paramétrables — à la différence des méthodes Query, dont les critères sont pré-définis par Sage. Leur second avantage est la performance : un prédicat retourne une collection de pointeurs vers les objets plutôt que les objets eux-mêmes ; l'instanciation réelle d'un objet n'a lieu qu'au moment où l'on accède effectivement à l'une de ses propriétés ou méthodes.

C#
1// Type de prédicat (extrait de la définition officielle)
2// typedef enum ePredicateType { PredicateTypeValue, PredicateTypeComparison, PredicateTypeCompound }
3
4IPredicateBuilder builder = baseCial.PredicateBuilder;
5IPredicate filtreType   = builder.Create(ePredicateType.PredicateTypeComparison);
6// ... configuration du filtre (champ, opérateur, valeur) selon l'objet ciblé
7
8IBICollection resultat = factoryTiers.QueryPredicate(filtreType);

Les prédicats autorisent également la jointure entre un sous-objet et son objet maître, avec un filtrage possible sur les deux à la fois — un cas d'usage impossible à exprimer avec une simple méthode Query. Trois grandes familles de prédicats structurent l'API : PredicateTypeValue (vrai/faux), PredicateTypeComparison (opérateurs de comparaison) et PredicateTypeCompound (composition And/Or/Not de plusieurs prédicats).

📌 À retenir

La collection IBICollectionPredicate qui regroupe des prédicats composés partage le même vocabulaire que IBICollection : Count, Item, AddNew(), Remove(), RemoveAll().

✅ Quiz de validation

IPMEncoder, IPMDocument, IPMDocTransformer… · S.10

Processus métier

Un processus (préfixe IPMxxx) est une entité métier qui automatise une opération complexe tout en garantissant l'intégrité des données — au lieu d'écrire manuellement chaque étape d'une transformation métier, on délègue au processus le soin de vérifier la cohérence (CanProcess()) puis d'appliquer les changements (Process()).

La documentation officielle liste, entre autres, les processus suivants : création de pièce comptable, lettrage d'écritures, création de document commercial, contrôle qualité, application de barèmes, transformation de documents commerciaux vente/achat (IPMDocTransformer), gestion du colisage, prélèvement de séries/lots (IPMSortirLots), transfert d'article entre dépôts, création de ligne de sous-total, recalcul de prix de revient de nomenclature, sortie d'un article géré par lot, et conversion d'un prospect en client.

C#
1IPMInventaire inventaire = baseCial.CreateProcess_Inventaire();
2inventaire.Depot = baseCial.FactoryDepot.ReadIntitule("Bijou SA");
3inventaire.DateInventaire = new DateTime(2026, 12, 31);
4
5IBODepotEmplacement empl = inventaire.Depot.FactoryDepotEmplacement.ReadCode("SECTIONBC7");
6// ... ajout des lignes de comptage (article, quantité, prix) sur cet emplacement
7
8if (inventaire.CanProcess())
9{
10    inventaire.Process();
11}

Chaque classe Application publie ses fabriques de processus sous la forme CreateProcess_<NomDuProcessus>() — CreateProcess_SortirLots(), CreateProcess_Inventaire(), etc. C'est le point d'entrée unique pour instancier un processus, à ne pas confondre avec les Factory d'objets métiers vues en S.04.

⚠️ Attention

Un processus qui échoue à CanProcess() ne doit jamais être forcé via Process() : parcourez sa collection Errors (IFailInfoCol) pour corriger la cause exacte avant de retenter.

Intégration applicative · S.11

Interop .NET / WinForms

Étant un composant COM, Objets100c.dll s'intègre nativement dans une application WinForms ou console .NET : après référencement, les classes du namespace Objets100cLib se manipulent comme n'importe quel objet C#. Le projet d'exemple fourni par le kit de développement (ExempleWindows.sln) illustre ce schéma, historiquement en VB.NET.

Un point de vigilance propre à l'interop COM : les objets Sage vivent dans un contexte COM géré par le Runtime Callable Wrapper (RCW) du .NET Framework. Il est recommandé de libérer explicitement les références lourdes (fermeture de connexion via Close(), mise à null des références d'objets Application) en fin de traitement, plutôt que de compter uniquement sur le ramasse-miettes .NET, pour éviter que la base Sage 100c ne reste verrouillée par une session fantôme.

C#
1private static bool FermeBaseCpta(ref BSCPTAApplication100c baseCpta)
2{
3    try
4    {
5        if (baseCpta.IsOpen) baseCpta.Close();
6        baseCpta = null;
7        return true;
8    }
9    catch (Exception ex)
10    {
11        Console.WriteLine("Erreur en fermeture de base : {0}", ex.Message);
12        return false;
13    }
14}

💡 Astuce

Dans une application WinForms, encapsulez l'ouverture/fermeture de connexion Sage dans un service dédié, instancié à l'ouverture du formulaire principal et libéré sur son événement FormClosing — jamais dans le constructeur d'un contrôle secondaire.

Matrice IBODocumentReglement · S.15

Règles de validation

Les contrôles de cohérence (S.00) prennent une forme particulièrement structurée sur les règlements : IBODocumentReglement applique une matrice de règles croisant le mode de règlement, le type de tiers (client/fournisseur) et le sens du document, pour déterminer les champs obligatoires et les montants autorisés.

C#
1IBODocumentVente3 doc = baseCial.FactoryDocumentStock.ReadPiece(
2    DocumentType.DocumentTypeVenteFacture, "FA00028");
3IBOTiersPart3 client = doc.TiersPayeur;
4
5IBODocumentReglement reglt = baseCial.FactoryDocumentReglement.Create();
6reglt.TiersPayeur = client;
7// ... affectation du mode de règlement, de la date, du montant
8reglt.WriteDefault();

La cohérence est vérifiée à l'écriture (Write()/WriteDefault()) : un règlement dont le montant dépasse l'encours restant, ou dont le mode de règlement est incompatible avec le type de tiers, est rejeté avec une exception explicite plutôt que silencieusement tronqué. C'est le même principe de « contrôle de cohérence » évoqué dès la présentation générale (S.00), appliqué ici au domaine sensible du règlement des échéances.

⚠️ Attention

Toujours encadrer l'écriture d'un règlement d'un try/catch dédié (cf. C.05) : le message d'exception détaille précisément la règle de la matrice qui a été violée, information souvent indispensable pour corriger la saisie en amont.

Tableaux vente/achat/stock · S.16

Quantités & signes de stock

Chaque ligne de document (vente, achat, stock) porte une quantité signée dont le signe dépend du type de mouvement qu'elle génère. Une ligne de vente en sortie de stock diminue le stock (signe négatif côté mouvement de stock), tandis qu'une ligne d'achat en entrée l'augmente (signe positif) — Sage documente ces correspondances dans des tableaux dédiés par domaine (vente, achat, stock interne).

DomaineType de mouvement typiqueEffet sur le stock
VenteLivraison / FactureSortie (diminution)
VenteAvoirEntrée (augmentation)
AchatRéception / FactureEntrée (augmentation)
AchatRetour fournisseurSortie (diminution)
Stock interneTransfert dépôt à dépôtSortie sur le dépôt source, entrée sur le dépôt destination

La propriété DocumentLigneMvtStockType (énumérateur) qualifie précisément ce type de mouvement au niveau de la ligne, tandis que DocumentLigneProvenanceType retrace l'origine de la ligne (saisie directe, transformation d'un document amont…). C'est cette combinaison qui permet à IBOArticle3.StockATerme() (S.14) de calculer un stock projeté fiable, en tenant compte des mouvements non encore soldés.

🔧 Sage

Le processus de Transfert d'un article d'un dépôt/emplacement vers un autre (S.10) manipule directement cette logique de signes, en générant deux mouvements corrélés (sortie source + entrée destination) au sein d'une même transaction cohérente.

Utiliser la valeur numérique d'un énumérateur au lieu de la constante.Toujours utiliser la constante nommée (S.08) — les valeurs internes ne sont pas garanties stables entre versions.
Oublier de fermer une connexion (Close()) en cas d'exception.Fermer systématiquement dans un bloc finally (C.05, S.11).
Modifier une collection Sage pendant son propre parcours foreach.Copier vers une List<T> avant modification (C.07).
Écrire en SQL direct dans les tables F_xxx pour « aller plus vite ».Toujours passer par la couche Objets Métiers pour toute écriture (S.17) — le SQL direct reste réservé à la lecture seule.
Forcer Process() sans avoir vérifié CanProcess().Toujours tester CanProcess() et parcourir Errors avant d'insister (S.10).
Confondre Read() et Refresh().Refresh() économise les accès base ; Read() force toujours la relecture (S.04).
Installer le Kit de développement complet sur un poste client en production.Déployer uniquement le Runtime utilisateur (S.02).

💡 Astuce

Journalisez systématiquement ex.Message des exceptions Sage : leur formulation est en général suffisamment précise pour identifier directement la règle de cohérence violée, sans avoir à reproduire le scénario en débogueur.

📌 À retenir

La quasi-totalité des pièges de cette liste se résume à une seule discipline : ne jamais court-circuiter la couche Objets Métiers, que ce soit en SQL direct, en valeurs numériques brutes, ou en ignorant une validation CanProcess().

Glossaire

ActiveX
Composant logiciel binaire basé sur la technologie COM de Microsoft ; Objets100c.dll en est un.
BSCPTAApplication100c
Classe Application permettant l'accès à une base comptable Sage 100c.
BSCIALApplication100c
Classe Application permettant l'accès à une base commerciale Sage 100c.
Cache applicatif
Mécanisme conservant en mémoire les objets déjà lus, pour accélérer les accès et garantir la cohérence entre plusieurs références au même enregistrement.
Classe
« Moule » servant à instancier des objets ; se décompose en implémentation (cachée) et interface (visible).
Collection
Objet regroupant plusieurs objets de même type, parcourable et accessible par index (interface IBICollection).
COM
Component Object Model : technologie Microsoft de composants binaires interopérables, base d'ActiveX.
Encapsulation
Principe selon lequel l'implémentation interne d'un objet reste invisible ; seule son interface est exposée.
Énumérateur
Ensemble de constantes nommées représentant les valeurs possibles d'une propriété (ex. TiersType).
Factory
Interface ou propriété (IBITypeObjectFactory) permettant de fabriquer (créer ou lire) des objets métiers.
IBIPersistObject
Interface héritée par tous les objets métiers persistants ; fournit Read(), Write(), Remove().
IBIPersistStream
Interface de sérialisation implémentée par les classes Application, pour l'accès en flux à la base.
IBICollection
Interface de collection standard de Sage 100 Objets Métiers.
Identifiant
Référence unique et stable d'un enregistrement, indépendante de ses attributs métier.
Interface
Schéma de méthodes et propriétés qu'un objet s'engage à fournir (ex. IBOTiers3).
Méthode
Fonction ou procédure exécutée depuis un objet, retournant une valeur ou exécutant une action.
Objet
Instance d'une classe, ou objet créé par une Factory.
Objet persistant
Objet dont l'état est enregistré durablement en base (via Write()/WriteDefault()), au-delà de la simple instance mémoire.
Prédicat
Filtre paramétrable (IPredicate) retournant une collection triée/filtrée sur des critères définis à l'exécution.
Processus
Entité métier (IPMxxx) automatisant une opération complexe via CanProcess() puis Process().
Propriété
État ou valeur d'un élément d'un objet, généralement lisible et parfois modifiable.
Runtime utilisateur
Package d'installation minimal de l'ActiveX Objets100c.dll destiné aux postes clients, sans les outils de développement.
Side by Side
Mécanisme permettant à plusieurs versions de l'ActiveX de cohabiter sur un même poste via manifeste applicatif.
Sous-objet
Objet rattaché à un objet maître (ex. une ligne de document rattachée à son document).
